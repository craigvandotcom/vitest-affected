## Dependency 2: Insertion point for injected reverse edges — merge into `reverse` before cache save, NOT a BFS seed
**Type:** Integration Point
**Current state:** needs modification
**File(s):** vitest-affected/src/plugin.ts:641-653 (cache load), :686-708 (runtime-edge merge + save closure), :927-939 (delta-parse seeds)
**Details:** The audit synthesis is explicit: the authoritative reverse graph is built solely from runtime `importDurations` (mergeRuntimeEdges); static parsing (`deltaParseNewImports`) is seed-only and never constructs persistent reverse edges. `extraDependencies` must therefore inject **durable reverse edges**, structurally identical to what the runtime reporter produces — i.e. entries merged into the `reverse: ReverseMap` variable at the same point runtime edges are merged (plugin.ts:693, `reverse = mergeRuntimeEdges(reverse, edges, 'all')`) and then persisted via `saveCacheSync(cacheDir, reverse, cacheMeta)` (plugin.ts:704). Injecting as BFS seeds instead (alongside `extraSeeds` at plugin.ts:938) would be wrong: seeds only cover the *current* changed-file set for *this* run and are never persisted, so the dependency would silently stop working the moment the trigger file isn't itself in the diff being analyzed — exactly the failure mode `extraDependencies` exists to close (per the synthesis: "any dependency channel invisible to runtime import tracking has no reverse edge").
**Evidence:** plugin.ts:686-708 (mergeRuntimeEdges + saveCacheSync call site); runtime-merge.ts:34-100 (`mergeRuntimeEdges(base, fresh, scope)` — a `ReverseMap` = `Map<string,Set<string>>`, exactly what a config-map-derived edge set would need to produce).

## Dependency 3: Persist or recompute? — recompute per run, but seed the persisted cache once at load
**Type:** Config / Architecture decision
**Current state:** needs new logic
**File(s):** vitest-affected/src/graph/cache.ts:240-329 (`loadCachedReverseMap`), :357-393 (`saveCacheSync`)
**Details:** Two viable insertion strategies, both compatible with the existing v3 cache format (no schema change needed — `reverseMap: Record<string,string[]>` already stores arbitrary source→tests string pairs, rootDir-relative). (a) **Recompute-per-run (recommended):** after `loadCachedReverseMap` (plugin.ts:649), resolve `extraDependencies` globs via `tinyglobby` and merge the resulting edges into `reverse` in-memory every `configureVitest` call, same shape as the runtime merge — cheap (config is static, glob resolution is fast) and never goes stale if the config map changes. (b) **Persist:** fold the resolved edges into the object passed to `saveCacheSync` so they survive as ordinary v3 cache entries. Recommend (a) as primary — config-derived edges should NOT get overwritten/pruned by mergeRuntimeEdges's per-test overwrite semantics (`scope: 'all'` strips a test's stale edges on every run it executes, which would erase a hand-configured edge the moment that test runs without touching the watched path) — so the safest design merges extraDependencies edges in-memory AFTER the runtime cache load and BEFORE BFS, on every run, independent of the persisted cache's mergeRuntimeEdges overwrite cycle.
**Evidence:** runtime-merge.ts:27-33 doc comment (`'all'` scope "strip stale edges from base, then merge fresh ones" — this would delete a persisted extraDependencies edge for any test that runs without the watched path appearing in that test's `importDurations`).

## Dependency 4: Relevance filter survival — extraDependencies watched paths need a graphMembership-equivalent bypass
**Type:** Integration Point
**File(s):** vitest-affected/src/changed-files.ts:41-70 (`ChangedFileFilterOptions.graphMembership`), :121-161 (`isRelevant`), plugin.ts:848-875 (filter call site)
**Details:** `filterRelevantChangedFiles` drops any changed file whose extension isn't in `DEFAULT_RELEVANT_EXTENSIONS` (.ts/.tsx/.js/.jsx/.mts/.cts/.mjs/.cjs/.json) UNLESS it matches `configBasenames` (always-relevant) OR `graphMembership.has(filePath)` — the exact mechanism that lets a CSS-module edge already recorded by the runtime reporter survive despite its extension (changed-files.ts:152-158, "graph membership overrides the extension allowlist"). `.css`, `.sh`, `.yml`, and `content/*.mdx` targets from the BCA audit list would all be **silently dropped before selection** unless one of two things happens: (1) `extraDependencies`' watched targets are folded into the `reverse` map (Dependency 2/3 above) BEFORE the filter call at plugin.ts:852-866, since `graphMembership: reverse` (plugin.ts:864) is passed straight through — this is the natural fix, requiring zero new filter code, only correct ordering (merge extraDependencies edges into `reverse` before step 6b's `filterRelevantChangedFiles` call); or (2) a new `extraRelevantPaths`-style option is added to `ChangedFileFilterOptions` mirroring `configBasenames`. Option (1) is strictly simpler and reuses a proven mechanism — the ordering constraint is the actionable finding.
**Evidence:** changed-files.ts:148-158 (extension allowlist check, then `if (options.graphMembership?.has(filePath)) return true;`); plugin.ts:862-864 (`graphMembership: reverse,  // The cache is already loaded (step 5) by this point`).

## Dependency 6: Publish-gate script inputs — strict SHA match against divergence log
**Type:** New Requirement
**File(s):** body-compass-app/_ci-evidence/vitest-affected-divergence-log.jsonl (log format); body-compass-app/.github/workflows/quality-gate.yml:184-204 (existing anchor-extraction logic to mirror); agent-compounds/skills/ac-publish/SKILL.md Phase 1a (:75-119, "Confidence gate")
**Details:** Log lines are JSONL with a `sha` field (e.g. `"sha":"31388bee8e97775980a06107cfd6ad4eedf296f7"`) and a `timestamp`; last line = last checkpoint. The gate script needs: (1) log path (`_ci-evidence/vitest-affected-divergence-log.jsonl`), (2) `git rev-parse main` for current HEAD, (3) behavior: read the LAST line's `sha`, compare to HEAD — exact string match required, refuse (non-zero exit / explicit fail message) if they differ or the log/last line is missing/unparsable. Quality-gate.yml already has the extraction pattern to mirror at :184-204 (Node inline script reads `_ci-evidence/vitest-affected-divergence-log.jsonl`, takes the last entry, exports `VITEST_AFFECTED_REF`) — the new gate script is the inverse check (assert-equal instead of extract-and-anchor).
**Evidence:** vitest-affected-divergence-log.jsonl tail (3 lines, each with `"sha":"..."` field, last = `31388bee8e97775980a06107cfd6ad4eedf296f7` at `2026-07-09T18:01:27.015Z`).
