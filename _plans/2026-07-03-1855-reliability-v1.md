# reliability-v1 — Measured reliability & the road to 1.0

## Summary

Make vitest-affected's safety **measured instead of asserted**: build a replay/divergence
harness, run it over body-compass-app's real commit history (Tier 1 selection-only +
Tier 2 outcome-diff), then close the silent under-selection channels ranked by the
resulting miss corpus, harden the fragile Vitest API touchpoints, and ship 1.0 with a
continuous shadow-verification mode wired into BCA's CI.

**Type:** IMPROVE
**Complexity:** A LOT

## Assumptions (from the Phase-0 interview + synthesis)

Interview decisions (Craig, 2026-07-03):
1. **Harden the current importDurations engine** — no engine swap in this plan; prior-art on coverage-map selection recorded for a future plan.
2. **Measure first, then fix** — Stage A (harness + Tier 1 + Tier 2 + report) completes and passes a human gate before Stage B implementation; Stage B candidates below are pre-seeded but final ranking comes from the miss corpus.
3. **Road to 1.0** — breaking changes allowed with auto-migration (cache v2→v3); defaults harden to the safest behavior; this upgrade IS the 1.0 milestone.
4. **Shadow mode scope = plugin feature + BCA CI wiring** (small cross-repo commit in body-compass-app's quality-gate).

Synthesis assumptions (would change the plan if wrong):
- **`vitest list` triggers `configureVitest`** (selection is decided in that hook before any test executes), so Tier 1 can log shadow decisions without running tests. Verified early in A1; fallback = spawn `vitest run` with a sentinel include that exits immediately after config resolution, or accept Tier 1 = Tier 2 on a smaller window.
- BCA's default suite (619 files, happy-dom, e2e/supabase-integration excluded) runs at historical commits with **no secrets/network/Supabase**; per-commit `pnpm install` needed only when the lockfile changes (~2% of commits).
- Full-suite wall-clock at BCA is **unmeasured** — Tier 2 window is sized at runtime after timing the first replay commit (target: fits one overnight run; ~100–150 recent non-config commits expected).
- The exact-scope shape of one finding is trusted from research without re-verification: BCA `resolve.alias` stubs (`@revenuecat/purchases-capacitor`, `server-only`) affect 5 importing files (constraints report).

## Context & Research

Research: `_plans/research/2026-07-03-{1847,1848,1850}-*-reliability-v1.md` (patterns, dependencies/prior-art, constraints/corpus, baseline).

**Coupling-channel verdicts** (constraints report, grounded in BCA usage):
- **Real silent holes with live evidence:** Vite `resolve.alias` unknown to the static delta-parser (oxc-resolver loads only tsconfig; 5 BCA files import aliased stubs — cache-miss/new-import window only, runtime covers once warm) · `new Worker(new URL(...))` invisible to import extraction (1 live BCA file) · env/`.env` drift (74 BCA test files read `process.env`; no trigger for external `.env` changes; partially mitigated by setupFiles hardcoding) · `globalSetup` untracked (latent — BCA unused today; asymmetric with the covered setupFiles channel).
- **Filter bug, not graph bug:** CSS(-module) edges ARE recorded at runtime (reporter has no extension filter), but `DEFAULT_RELEVANT_EXTENSIONS` drops changed `.css` before BFS — the seed never enters the graph it's already in.
- **Dissolved:** factory `vi.mock` is BY-DESIGN decoupling (341 BCA test files; a fully-mocked module can't change the test's outcome) — needs documentation + an `importActual` partial-mock regression test, not new edges.
- **Low/covered:** setupFiles, JSON, tsconfig aliases, ?raw/?url, type-only exclusion, fs-fixtures (via `fullSuiteTriggers`, with one unverified edge: whether all 34 fs-reading BCA test files sit under the declared `__tests__/fixtures/` trigger), `.snap`-only edits (1 file), `import.meta.glob` (0 uses).

**API fragility** (dependencies report): reporter attachment via undocumented `Object.defineProperty` interception has a **documented supported alternative** (`vitest.config.reporters.push`) · `importDurations` is experimental and evolving → startup shape-check wanted · `project.config.include` mutation is undocumented → selection self-verify wanted · Vitest 5 beta excluded by peerDep (intentional; validation pass before widening) · no upstream native affected-selection — niche open.

**Prior-art steals:** testpick's "never less" posture + `explain` command (why was this test selected) · Nx/Turborepo/Microsoft-TIA convergence on **periodic ground-truth reconciliation** for drift.

**Corpus bounds:** adoption `7a89c10c` (2026-02-23), **2,672 commits** on main since; ~2% touch lockfile/config (auto-full-suite, excluded from replay); BCA's live `.vitest-affected/stats.jsonl` (41KB of real selection decisions) + `graph.json` (692KB) exist as bonus Tier-0 material.

**Baseline** (baseline report): tsc/build green; tests 110/117 — all 7 failures are a macOS symlink-path artifact in `test/git.test.ts` exposing a real canonicalization gap (no `realpathSync` anywhere at path boundaries).

## Outcome Definition

- A **measured miss-rate** over real BCA history, with a per-miss corpus (commit, diff, missed test, coupling channel) on disk.
- Every taxonomy channel either TRACKED, FALLBACK-COVERED, or documented BY-DESIGN — zero *undocumented* silent holes.
- The 0.5.0 silent-no-op bug class is structurally impossible (heartbeat + shape-check + selection self-verify).
- A divergence counter accumulating in BCA CI (shadow mode) — the evidence stream that eventually retires `test:all` from the merge gate.
- v1.0.0 published.

## Technical Specification

### Stage A — Measure (gate: human review of the miss-rate report)

**A1. Shadow-verification mode (plugin feature — built first because measurement requires it)**
- New option `shadow?: boolean` (env `VITEST_AFFECTED_SHADOW=1`): run the full decision pipeline, write the stats line with `action: 'shadow-selective' | 'shadow-full-suite'` + the would-be file list, but **never mutate `project.config.include`**.
- Reuses the existing `writeStatsLine` JSONL schema (patterns report P1) — new `reason`/`action` values only, no new schema.
- Selection decided in `configureVitest` ⇒ works under `vitest list` (no execution) and `vitest run` (full suite + shadow log in one invocation).

**A2. Replay harness — `tools/replay/` (devtool; NOT in `files`/`exports`/tsup entries — patterns P7)**
- Driven via `npx tsx tools/replay/run.ts --repo <path> --range <from>..<to> [--tier 1|2] [--sample <n>]`.
- Clone manager: `git clone <local-bca-path> <workdir>` (disposable, offline); commit walker skips lockfile/config-touching commits (flagged, not silently dropped); `pnpm install` only on lockfile-hash change.
- Per commit (forward walk, oldest→newest): checkout → Tier 1: `vitest list` with shadow on, capture stats line · Tier 2: `vitest run --reporter=json` full suite with shadow on → ground truth outcomes + would-be selection from one run; the run also evolves `.vitest-affected/graph.json` exactly as live usage would.
- **Miss detector:** any test whose pass/fail outcome changed C-1→C that the shadow selection at C did not include ⇒ recorded miss `{commit, diff files, missed test, prior/new outcome, suspected channel}`. Flake guard: re-run a new failure once before recording (this Mac shows phantom vitest failures under load).
- Report generator: aggregate JSONL → markdown report (miss-rate, misses by channel, selection-ratio distribution, full-suite-trigger frequency).
- Reuses the `test/integration.test.ts` scaffold conventions (execa, temp dirs, JSON reporter parsing — patterns P5).

**A3. Tier 1 sweep** — all non-config commits since adoption (~2,600; config-resolution cost only). Plus Tier 0: analyze BCA's existing live `stats.jsonl`.

**A4. Tier 2 window** — most recent non-config commits, window sized after timing commit #1, overnight run target.

**A5. Miss-rate report → HUMAN GATE.** Craig reviews; Stage B beads get final priority order from the corpus.

### Stage B — Fix (candidates pre-seeded; ranking finalized at the gate)

**B1. API hardening / self-verification** — supported reporter registration (verify the serializable-reporter shape the docs require; keep defineProperty as guarded fallback) · `experimental.importDurations` startup shape-check · **zero-edge heartbeat** (a completed run that collected no edges warns loudly + stats line) · selection self-verify (reporter asserts ran-tests ⊆ selected; mismatch = loud warning).
**B2. Trigger/graph closures** — `globalSetup` full-suite trigger mirroring the setupFiles idiom (plugin.ts:448-466 pattern) · Vite `resolve.alias` fed into the oxc-resolver config · `new Worker(new URL(...))` extraction in the delta-parser · `.env*` change handling (decision: CONFIG_BASENAMES entry vs documented `fullSuiteTriggers` recipe) · BCA fixture-trigger audit (all 34 fs-reading test files under the declared trigger?).
**B3. Relevance-filter fix** — graph-membership overrides the extension allowlist (closes CSS + any future asset class in one move); `.snap` decision documented.
**B4. Path canonicalization** — `realpathSync` at all boundaries (rootDir, git output, cache keys); centralize the scattered `replaceAll('\\','/')` sites; fixes `test/git.test.ts` on macOS.
**B5. Cache v3** — relative paths (CI-portable), read-time v2→v3 auto-migration mirroring the v1→v2 branch (cache.ts:134-174 template).
**B6. Debuggability + drift** — `explain` trail (per selected test: seed → edge chain, in stats/CLI) · staleness reconciliation (age/run-count-triggered full rebuild + diff, per Nx/TIA precedent).
**B7. BCA CI shadow wiring** — quality-gate keeps `test:all` but adds `VITEST_AFFECTED_SHADOW=1` + a divergence-check step publishing the counter (cross-repo commit in body-compass-app).
**B8. 1.0 release** — defaults hardening, README verdict table (the taxonomy, including BY-DESIGN vi.mock), CHANGELOG, macOS+Linux CI matrix, v1.0.0 publish; Vitest 5 validation pass before widening peerDep (may defer to 1.1).

## Success Criteria

1. **Silver bullet:** harness self-test — a synthetic consumer-repo fixture with a planted miss sequence (commit that changes a dependency via a known-hole channel); the harness detects the planted miss in Tier 1 and Tier 2 modes and its report shows miss-rate > 0. After B2/B3 land, the same fixture reports the planted channels as covered.
2. Tier 1 sweep + Tier 2 window completed over real BCA history; miss-rate report exists and was human-reviewed (gate artifact).
3. Zero-edge heartbeat: simulated no-op reporter run produces a loud warning (test).
4. BCA quality-gate produces shadow divergence output on a real PR run.
5. `npm view vitest-affected version` → 1.0.0; suite green on macOS and Linux.

## Implementation Phases (phased rollout)

### Phase A1: Shadow mode
**Done when:** `test/shadow.test.ts` passes; a manual `VITEST_AFFECTED_SHADOW=1 npx vitest list` in a fixture writes a shadow stats line and executes nothing.

### Phase A2: Replay harness + self-test fixture
**Done when:** silver-bullet `test/replay.test.ts` passes (planted miss detected, control corpus clean).

### Phase A3: Tier 0 + Tier 1 sweep over BCA
**Done when:** report artifact exists covering all non-config commits since `7a89c10c` + analysis of BCA's live `stats.jsonl`; commits skipped are itemized, not silent.

### Phase A4: Tier 2 overnight window
**Done when:** outcome-diff report over the sized window exists; every recorded miss has commit/diff/test/channel attribution; flake-guard re-runs logged.

### Phase A5: Miss-rate report + HUMAN GATE
**Done when:** consolidated report reviewed by Craig; Stage B bead ranking recorded in the report and this plan updated (`refinement note`), before any Stage B implementation starts.

### Phase B (order finalized at gate; default order B1→B8)
**Done when (per bead):** the matching test-spec cases pass; quality gate (`tsc --noEmit && npm run build && npx vitest run`) green on macOS; CHANGELOG entry written.
**B7 done when:** a real BCA PR run publishes the shadow divergence artifact.
**B8 done when:** v1.0.0 on npm; README verdict table present; CI matrix green.

## Risks & Mitigations

| Risk | Mitigation |
| --- | --- |
| `vitest list` doesn't fire `configureVitest` / doesn't resolve plugins identically | Verified first thing in A1; fallbacks noted in Assumptions |
| Tier 2 wall-clock blows past overnight (suite duration unmeasured) | Time commit #1, size window before committing to the run; window is a parameter |
| Historical commits fail to install/run (dep drift, node version) | Walker records per-commit status (ok/skipped/broken) — broken commits are data, not crashes |
| Phantom failures on loaded Mac pollute ground truth | Flake guard: re-run new failures once; run overnight; `maxWorkers: 1` already BCA default |
| Supported reporter-registration path expects serializable reporter refs incompatible with our closure-based reporter | Investigate in B1; keep defineProperty as guarded fallback + heartbeat makes silent failure impossible either way |
| Shadow mode itself perturbs measurement (cache writes during replay) | Replay workdir owns its `.vitest-affected/`; Tier 2 cache evolution is *intended* (mirrors live usage); Tier 1 runs read-only |
| Cross-repo B7 commit drifts from BCA conventions | Follow quality-gate.yml's existing comment style; BCA change is additive (new step), `test:all` untouched |

## Decision Log & Alternatives

1. **Measure-first (Craig)** over parallel fix+measure — corpus ranks the backlog; known holes wait despite being confirmed by code reading.
2. **Harden importDurations engine (Craig)** over per-test coverage-map swap (testpick/Wallaby style) — swap recorded as future-plan candidate; prior-art preserved in the dependencies report.
3. **Shadow-mode-first harness design** over external selection re-implementation — the harness drives the *real* plugin (no logic drift); shadow mode is product code, not throwaway recon. Alternative rejected: importing selector/cache internals into the harness and re-deriving the decision pipeline (drift risk).
4. **`tools/replay/` as devtool** over shipped CLI (`bin`) — package stays a pure plugin (patterns P7); revisit if consumers want replay.
5. **Graph-membership relevance override** over widening extension allowlists per asset class — one rule covers CSS today and future asset classes; conservative default preserved.
6. **vi.mock factory verdict = BY-DESIGN** — no mock-aware edge extraction; documented + regression-tested instead (constraints report row 1).
7. **Road to 1.0 (Craig)** — cache v3 breaking change acceptable with read-time auto-migration (v1→v2 precedent).

## Dependencies / Blockers

- No new npm deps required for the harness (`execa`, `tinyglobby` present; `tsx` available via npx). CLI parser only if a `bin` is ever shipped (decision 4 says no).
- BCA local checkout is the corpus source (offline clone) — no secrets needed for the default suite.
- B7 requires a body-compass-app commit (cross-repo; small, additive).
- Overnight machine time on this Mac for A4 (coordinate with other scheduled load; `pai-scheduler` slot if needed).
- Pre-existing `test/git.test.ts` macOS failures are baseline debt fixed in B4 — until then the quality gate on this Mac is "110 passing + 7 known-env" (documented in baseline report).
