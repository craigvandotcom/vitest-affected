# reliability-v1 — Measured reliability & the road to 1.0

## Summary

Make vitest-affected's safety **measured instead of asserted**: build a replay/divergence
harness and walk it forward over body-compass-app's real commit history — one full run
per commit yielding the shadow decision AND ground truth, scored by a two-tier miss
detector (structural + outcome-confirmed) — then close the silent under-selection
channels ranked by the resulting miss corpus, harden the fragile Vitest API touchpoints,
and ship 1.0 with a continuous shadow-verification mode wired into BCA's CI.

**Type:** IMPROVE
**Complexity:** A LOT

## Assumptions (from the Phase-0 interview + synthesis)

Interview decisions (Craig, 2026-07-03):
1. **Harden the current importDurations engine** — no engine swap in this plan; prior-art on coverage-map selection recorded for a future plan.
2. **Measure first, then fix — two-track form:** Stage B splits into a **corpus-independent track** (B1 heartbeat/self-verify, B4 canonicalization, the globalSetup trigger, the CSS relevance fix, the vi.mock/importActual regression test — may proceed in parallel with Stage A; the corpus cannot rank them) and a **corpus-ranked track** (everything else — waits for the A5 gate, ranked by the miss corpus). Measure-first is retained exactly where measurement informs.

4. **Shadow mode scope = plugin feature + BCA CI wiring** (small cross-repo commit in body-compass-app's quality-gate).

## Technical Specification

> **Canonical homes (single source during beadification):** the shadow **full-suite contract** lives in A1; the **denominator/exemption rules** live in A2. Mentions elsewhere are references, not restatements.

### Stage A — Measure (gate: human review of the miss-rate report)

**A1. Shadow-verification mode (plugin feature — built first because measurement requires it)**
- New option `shadow?: boolean` (env `VITEST_AFFECTED_SHADOW=1`): run the full decision pipeline, write the stats line with `action: 'shadow-selective' | 'shadow-full-suite'`, but **never mutate `project.config.include`**.
- Extends the `writeStatsLine` JSONL schema (patterns report P1) **additively**: new `action` values plus an optional `selectedFiles` field — load-bearing for miss attribution; the existing count-only `affectedTests` field is insufficient. **Full-suite contract** (leaving this undefined would break the detector, the cache reconstruction, and cold-cache warm-up): `shadow-selective` carries `selectedFiles: string[]`; `shadow-full-suite` carries `selectedFiles: null`, meaning "all tests".
- **Env overrides so historical configs can't starve emission:** `VITEST_AFFECTED_SHADOW=1` activates shadow regardless of config options; `VITEST_AFFECTED_STATS_FILE=<path>` forces stats output to that path (wins over config `statsFile`).
- **Every-exit-emission contract:** stats-path resolution is hoisted ABOVE the try block (env var read first; `process.cwd()` fallback when rootDir is unresolved) so the catch-all (plugin.ts:603-608) can emit `reason: 'error'`, and the four currently-silent early returns (workspace guard :233, config-shape :240, no-include :491, no-test-files :505) each emit a line. Contract: when a stats path is known, every exit path writes exactly one stats line — with ONE intentional exception: the `disabled` early-return (plugin.ts:227-230) emits nothing, by design (B7's rollback switch relies on `disabled` being fully inert). "Missing line = BROKEN" therefore holds whenever `disabled` is not set.
- **Wiring contract:** shadow guards BOTH include-mutation sites (plugin.ts:524 `allowNoTests`, :586 selective) and remaps every `writeStatsLine` call-site's `action` into the shadow namespace with the original `reason` retained (e.g. `action: 'shadow-full-suite', reason: 'cache-miss'`) — A2's fallback-frequency segmentation depends on reasons surviving the remap.
- Extracts the reporter's per-test merge (plugin.ts:294-312) into an exported **pure** function — `mergeRuntimeEdges(base: ReverseMap, fresh: ReverseMap, scope: Set<string> | 'all'): ReverseMap` — with persistence left at the call-site (the current closure also calls `saveCacheSync`; the harness must NOT write the live cache). Single source of merge semantics for reporter + harness.
- Selection is decided in `configureVitest` ⇒ one `vitest run` full-suite invocation yields ground truth AND the shadow decision. (`vitest list` also fires the hook — verified on 3.2.4 — but executes nothing, so it serves only as a cheap config-resolution smoke check.)

**A2. Replay harness — `tools/replay/` (devtool; NOT in `files`/`exports`/tsup entries — patterns P7)**
- Driven via `npx tsx tools/replay/run.ts --repo <path> --range <from>..<to> [--sample <n>]`. One walk produces both the decision stream and the ground truth — no separate list-only or smoke mode (walk commit #1 is fail-closed and proves plugin resolution; see A3 for why a list-only sweep cannot measure).
- **Workdir layout preserves sibling plugin resolution:** clone to `<workdir>/body-compass-app` and symlink `<workdir>/vitest-affected/dist` → the real built dist. BCA's `vitest.config.mts` resolves the plugin via `../vitest-affected/dist` with a silent no-op fallback — a bare clone would load the no-op and produce a false-clean report. **Fail-closed guard:** every replayed commit MUST emit a shadow stats line; a missing line marks the commit BROKEN, never clean.
- **Ref control without config drift:** BCA's config hardcodes `ref: 'main'`; per commit C the harness runs `git branch -f main C^` in the clone and checks out C detached — the unmodified config then diffs exactly C-1→C.
- Commit walker: walks the **first-parent chain** of main — a merge's step-diff is the whole PR delta vs previous main, exactly what live usage saw; skips lockfile/config-touching commits (flagged, not silently dropped); initial `pnpm install --prefer-offline`, re-install on lockfile-hash change; per-commit status ok / skipped / BROKEN.
- **Environment hygiene:** the workdir path is `realpathSync`'d at creation (an un-canonicalized `/var`→`/private/var` temp path desyncs rootDir from git/Vite paths, starving the reporter of edges — the baseline git.test.ts bug applied to the harness itself); `CI`/`GITHUB_ACTIONS` env cleared for walk runs (BCA's `retry: CI ? 1 : 0` would silently mask outcome flips); each commit writes to its own stats file via `VITEST_AFFECTED_STATS_FILE=<run>/stats/<sha>.jsonl` — commit attribution without schema surgery, and no interleaving with BCA's live `stats.jsonl`.
- Per commit (forward walk, oldest→newest): checkout → `vitest run --reporter=json` full suite with shadow on → (a) ground-truth outcomes, (b) shadow decision + `selectedFiles`, (c) the post-run graph = complete fresh runtime edge map at C.
- **Simulated selective cache evolution:** a full-suite run overwrites the whole cache, erasing the staleness drift being measured. So: snapshot the cache pre-run; next commit's cache = snapshot + `mergeRuntimeEdges()` (imported from the built dist, not re-implemented) restricted per the shadow decision — `shadow-selective`: merge only the selected set's edges (what a live selective run persists); `shadow-full-suite`: merge the FULL fresh map (what a live full-suite run persists — this is also exactly how commit #1 warms the cold cache). The full fresh map is kept separately as ground-truth edge data.
- **Two-tier miss detector:** *structural* (primary) = any test whose fresh runtime import set at C intersects the changed files (from the ground-truth map) that shadow selection did NOT include; *outcome-confirmed* (severity subset) = structural misses whose pass/fail outcome actually changed C-1→C. File-path identity; added/renamed tests are handled naturally because the structural set is computed fresh at C. Reported as structural miss-rate + outcome-confirmed subset — never a bare "miss-rate" (outcome flips alone are a lower bound).
- **Denominator & exemptions:** miss-rates are computed over `shadow-selective` decisions ONLY. Designed full-suite fallbacks (config change, full-suite triggers like BCA's `__tests__/fixtures/`, cache-miss, threshold) are miss-exempt by definition — selection ⊇ everything — and are reported as segmented fallback-frequency. Leading warm-up commits (before the first selective decision) are segmented out of the rate.
- **Degeneration guard:** zero selective decisions across the ENTIRE walk FAILS the run loudly — a silent all-full-suite walk is list-only degeneration in disguise, and the per-commit BROKEN guard alone cannot catch it.
- Flake guard: re-run a new failure once with `VITEST_AFFECTED_DISABLED=1` — no cache/stats side effects pollute the walk.
- Report generator — gate essentials only: structural + outcome-confirmed miss-rates (selective-decision denominator), misses by channel, fallback-frequency segmentation, BROKEN-commit inventory. Selection-ratio/trigger distributions live in Tier 0, not duplicated here.
- Reuses the `test/integration.test.ts` scaffold conventions (execa, temp dirs, JSON reporter parsing — patterns P5).

**A3. Tier 0 analysis + CI-runner recon** — analyze BCA's live `stats.jsonl` (41KB of real selection decisions) for distributions (selection ratio, trigger/reason frequency — these live here, not in the walk report); recon BCA's CI runner workspace layout (self-hosted: does the workspace persist across runs? are absolute paths stable?) so the A5 gate can decide B5 informed rather than circularly. **No standalone list-only sweep:** the runtime cache populates only when tests execute, so a cold list-only sweep degenerates to cache-miss/full-suite on every commit — zero measurement value — and its descriptive signal already exists in Tier 0.

**A4. Replay walk** — most recent first-parent non-config commits. Window sized from the plan-time timing run: full suite = **320s at BCA HEAD** (585 files / 8,157 tests, this Mac) → **~100-commit window ≈ 9h**, one overnight run. Produces the decision stream, ground truth, and the miss corpus in one pass.

**A5. Miss-rate report → HUMAN GATE.** Craig reviews; Stage B beads get final priority order from the corpus.

| Risk | Mitigation |
| --- | --- |

| Walk wall-clock blows past overnight | Suite measured at 320s → ~100-commit window ≈ 9h; window is a parameter |
| Historical commits fail to install/run (dep drift, node version) | Walker records per-commit status (ok/skipped/broken) — broken commits are data, not crashes |

| Cross-repo B7 commit drifts from BCA conventions | Follow quality-gate.yml's existing comment style; the change modifies `scripts/test.sh:11` in place (DISABLED→SHADOW) — full-suite guarantee preserved by shadow semantics, DISABLED documented as rollback |

## Decision Log & Alternatives

1. **Measure-first (Craig)** over parallel fix+measure — corpus ranks the backlog; known holes wait despite being confirmed by code reading.
2. **Harden importDurations engine (Craig)** over per-test coverage-map swap (testpick/Wallaby style) — swap recorded as future-plan candidate; prior-art preserved in the dependencies report.
3. **Shadow-mode-first harness design** over external selection re-implementation — the harness drives the *real* plugin (no logic drift); shadow mode is product code, not throwaway recon. Alternative rejected: importing selector/cache internals into the harness and re-deriving the decision pipeline (drift risk).
4. **`tools/replay/` as devtool** over shipped CLI (`bin`) — package stays a pure plugin (patterns P7); revisit if consumers want replay.
5. **Graph-membership relevance override** over widening extension allowlists per asset class — one rule covers CSS today and future asset classes; conservative default preserved.
6. **vi.mock factory verdict = BY-DESIGN** — no mock-aware edge extraction; documented + regression-tested instead (constraints report row 1).
7. **Road to 1.0 (Craig)** — cache v3 breaking change acceptable with read-time auto-migration (v1→v2 precedent).
8. **(Round 1) Standalone Tier 1 sweep cut** — 3/3 reviewer consensus: list-only invocations can never warm the runtime cache (populated only by executing tests), so a cold sweep degenerates to all cache-miss/full-suite; its descriptive signal already exists in Tier 0. One walk yields decisions + ground truth together.
